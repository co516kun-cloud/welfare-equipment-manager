# スキャン後に続けて処理する 設計書（2026-11-19）

## 1. 意図

田口さんの依頼: 「スキャンをして返却やメンテナンスなどの処理をするときに、前の処理を忘れていて連続で処理したい時がある（入庫処理をしようとしたらまだ返却のままだったなど）。一回一回スキャンしなおさないといけないのが手間。一回スキャンしたら続けて処理する機能があればありがたい。そこで終わりたいときは続けないを選択すればいい。」

倉庫で現物を手に持ったまま、返却済み → 消毒完了 → メンテナンス完了 → 入庫処理 を 1 回のスキャンで通せるようにする。

## 2. 田口さんの決定

1. 一回スキャンしたら続けて処理できる。終わりたいときは「続けない」を選ぶ
2. 無駄にダイアログがいっぱい出ないようにする
3. 処理中で次の画面が出るまで時間がかかる場合は、処理中だと分かるようにする

## 3. ゴール・非ゴール

- ゴール: 1 台について工程を続けて進められる。何工程進んでもダイアログは 1 枚のまま。処理中は見て分かる
- 非ゴール: 「入庫まで一気に進める」ボタン（MCP の run_flow 相当。必要になったら完了ビューに 1 つ足せる）。廃棄・寄贈を続けて行うこと。個体詳細・MCP・DB の変更
- アンチゴール: 流れ作業の勢いで取り返しのつかない操作（廃棄・寄贈・直接貸与）を押してしまうこと

## 4. 現状（コードで確認）

- `src/pages/scan.tsx`: 読み取った台は `selectedItem` に写しとして持つ。処理が成功すると `handleActionSuccess` が店舗データを再読込し、連続モードなら 3 秒後に `selectedItem` を消す。単発モードでは古いステータスのまま残り、次の工程を押すとダイアログ側の最新確認で「既に別の処理が行われています」と止まる
- `src/components/scan-action-dialog.tsx`: 「処理実行」→ サーバーの最新ステータス確認 → 個体の保存と履歴の追加（メンテナンスは写真を Base64 で含むので重い）→ 入庫なら印刷確認 → フォームを消して閉じる → `onSuccess()`。**処理中の表示が無く、ボタンも無効化されない**
- スマホは `src/components/mobile-scan-ui.tsx` の中で、PC は `scan.tsx` の末尾で、同じ `ScanActionDialog` を描画している

## 5. 作り方の候補

| 案 | 内容 | 判断 |
|---|---|---|
| A | 成功したら処理ダイアログを閉じ、別の「続けますか」ダイアログを開く | 閉じて開くので 2 枚見える。決定 2 に反する |
| B | **処理ダイアログの中身を「完了・次の工程」に切り替える** | 1 枚のまま。次の工程を押すと同じダイアログがその工程のフォームになる。**採用** |
| C | ダイアログを閉じ、スキャン画面の個体カードを最新化して次の工程ボタンを出す | ダイアログは減るが「続けない」を明示的に選ぶ形にならず、連続モードの自動クリアと混ざる |

## 6. 設計

### 6.1 完了ビュー（同じダイアログの中身が切り替わる）

処理が成功したら、ダイアログを閉じずに次の内容に切り替える。

```
┌────────────────────────────────┐
│ 処理が完了しました                 │
│ 車いす 標準型  WC-001             │
│ 返却済み → 消毒済み               │
│                                │
│ 続けて処理しますか？               │
│ [ メンテナンス完了 ]              │
│                                │
│ [ 続けない（次の台をスキャン） ]     │
└────────────────────────────────┘
```

- 次の工程ボタン: 新しいステータスで取れる操作（`getAvailableActions`）から、確認が要る危険な操作（`needsConfirm`: 廃棄・寄贈）を除いたもの。ボタンの文言は遷移表の `label` をそのまま使う
- 「続けない（次の台をスキャン）」: 今までどおり閉じて `onSuccess()`。連続モードの 3 秒クリアもここから今までどおり動く
- 次の工程ボタンを押す → 親に `onContinue(actionKey)` → `actionType` が変わり、同じダイアログがその工程のフォーム（チェックリスト・写真・場所などは従来どおり）になる。ネットワークは挟まないので即切り替わる

### 6.2 完了ビューを出す条件

新しいステータスが「倉庫の中で工程が残っている状態」のときだけ出す。

- 出す: `returned`（返却済み）/ `cleaning`（消毒済み）/ `maintenance`（メンテナンス済み）/ `out_of_order`（故障中）/ `unknown`（状態不明）/ `demo_cancelled`（デモキャンセル）
- 出さない（今までどおり閉じる）: `available` / `rented` / `ready_for_delivery` / `reserved` / `disposed` / `donated`

入庫処理は `available` になるので、印刷確認のあと今までどおり閉じる。入庫した直後に「直接貸与」を見せると押し間違いの元になる、という判断（Claude の判断。田口さんに提示済み）。

この一覧は `src/lib/item-status.ts` に `CONTINUABLE_STATUSES` として置く（ステータスの文字列リテラルを他のファイルに書くと型チェックゲートが誤判定する。CLAUDE.md「罠」）。

### 6.3 処理中の表示（決定 3）

- 「処理実行」を押してから、完了ビューが出るか閉じるまでを `isProcessing` とする
- その間: 実行ボタンは無効化して文言を「処理中…」に、キャンセルも無効化、外側クリック・Esc で閉じない
- 完了ビューを出す前に最新の個体をサーバーから 1 回取り直す（`getProductItemById`）。これも処理中に含める。取れなければ楽観的に新しいステータスで組み立てる
- 二度押し防止にもなる（今は 2 回押せる）

### 6.4 選択中の台の最新化

- 成功のたびにダイアログが親へ `onItemUpdated(latestItem)` を返し、`scan.tsx` は `selectedItem` を置き換え、店舗の `items` にも 1 行マージする（既存の「既に別の処理」分岐と同じやり方）
- これで単発モードでも個体カードのステータスが古いまま残らない（副次的に直る）
- 店舗データの全件再読込（`loadData`）は今までどおり閉じたときの `onSuccess` で 1 回だけ。工程ごとには呼ばない

### 6.5 変更する場所

| ファイル | 変更 |
|---|---|
| `src/lib/item-status.ts` | `CONTINUABLE_STATUSES`、`canContinueAfter(status)`、`getContinueActions(status)`（danger を除く） |
| `src/components/scan-action-dialog.tsx` | `isProcessing`、完了ビュー、props `onContinue` / `onItemUpdated` |
| `src/components/mobile-scan-ui.tsx` | 上の 2 props を通す |
| `src/pages/scan.tsx` | `onContinue` → `setActionType`、`onItemUpdated` → `setSelectedItem` と店舗へのマージ |
| `scripts/demo-check.mjs` または使い捨てスクリプト | 完了ビューと処理中の画像を撮る |

DB・SQL・MCP の変更は無い。`mcp-server/src/shared/item-status.ts` は `npm run build` の再生成で追従する。

## 7. 田口さんに見せるもの

デモモードで、(1) 消毒完了の処理中、(2) 完了ビュー（次の工程ボタンと「続けない」）、(3) 続けてメンテナンス完了のフォームになったところ、の 3 枚。見てもらってからコミット・デプロイ（CLAUDE.md の流儀）。

## 8. 建設者に任せる点

- 完了ビューの細かな見た目（色・余白）。既存のダイアログの流儀に合わせる
- `isProcessing` の間のスピナーの有無（文言「処理中…」は必須）
- テストの粒度。少なくとも: 完了ビューを出す・出さないの表、danger を含まないこと、処理中にボタンが無効化されること、次の工程で同じダイアログがフォームに戻ること
